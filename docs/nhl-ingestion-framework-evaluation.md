# Scheduling NHL scores and box scores

Evaluated November 10, 2026. Use **GitHub Actions** for a nightly postgame refresh and manual backfills. A Node command can fetch and validate game data, then the workflow can publish the changed files in one Git commit. The ingestion itself needs no language model or long-lived worker.

## What the repository already does

The November 9 season snapshot contains 1,344 unique regular-season games and 282 final results. The club schedule importer keeps one record per NHL game ID and includes a result only for `OFF` and `FINAL` games. It does not collect per-game player box scores. The poster refresh uses the game snapshot as input and updates standings, special teams, and player leaders. The API checks that the two snapshots agree, and Vercel bundles them in the deployment. [Data contract](../data/README.md) · [Season snapshot](../data/nhl-20262027.json) · [API validation](../apps/api/src/snapshots.ts) · [Vercel handler](../apps/api/src/web-handler.ts)

At the saved snapshot's size, the two refresh commands would make 106 NHL requests. That includes 32 club schedules, 41 dated standings, 32 club-stat feeds, and one team summary. A box score backfill would add up to 282 game requests. This is a count from the current scripts and snapshot, with live latency and provider limits still to measure. [Game refresh](../scripts/refresh-nhl-games.mjs) · [Poster refresh](../scripts/refresh-nhl-poster.mjs)

## Options

| Option | Scheduled execution | Failure handling | Publishing to `data/` |
| --- | --- | --- | --- |
| **GitHub Actions** | Cron starts a job on the default branch. A Node script runs without a model. `workflow_dispatch` supports an on-demand run. | Schedules can be delayed or dropped. Public repositories disable schedules after 60 days of inactivity. Put bounded transient retries in the script and reconcile outstanding games on every run. A manual dispatch can run against the current branch tip, while GitHub's rerun uses the original ref and SHA. [Schedule and manual dispatch](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule) · [Reruns](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/re-run-workflows-and-jobs) | The runner checks out the repo and can push with its built-in `GITHUB_TOKEN` granted `contents: write`, subject to branch rules. [Checkout example](https://github.com/actions/checkout#push-a-commit-using-the-built-in-token) · [Token permissions](https://docs.github.com/en/actions/concepts/security/github_token) |
| **Vercel eve** | A Markdown or `content` schedule prompts the agent. A TypeScript `run` handler can await regular code and skip the agent call. Static hosted schedules use Vercel Cron Jobs. Self-hosted builds can use Nitro's scheduler. [eve schedules](https://github.com/vercel/eve/blob/main/docs/schedules.mdx) | Static Vercel Cron delivery can miss or duplicate an occurrence, and failed invocations receive no automatic retry. Hobby limits each schedule to daily with hour-level timing. eve's durable sessions apply to agent conversations. A plain handler needs its own retry and catch-up logic. [Cron limits](https://vercel.com/docs/schedules/cron-jobs/usage-and-pricing#limits) · [Cron error handling and delivery](https://vercel.com/docs/schedules/cron-jobs/manage-cron-jobs#cron-job-error-handling) · [eve durability](https://vercel.com/blog/introducing-eve) | Vercel Functions provide read-only deployed files and writable temporary scratch space. Git persistence requires a separate GitHub credential and a push from a writable checkout or a Git API commit. [Function filesystem](https://vercel.com/docs/functions/runtimes#file-system-support) · [Git trees](https://docs.github.com/en/rest/git/trees#create-a-tree) · [Git ref updates](https://docs.github.com/en/rest/git/refs#update-a-reference) |
| **Mastra** | Schedule a typed workflow with `inputData`. Ordinary steps run without a model. The built-in scheduler polls a schedule store from a long-lived process. On Vercel Functions, trigger a direct run externally or use an integration such as Inngest for cron. [Scheduled workflows](https://mastra.ai/docs/workflows/scheduled-workflows) · [Schedule storage](https://mastra.ai/docs/storage) | Schedule publication is best effort. Mastra documents up to three publication attempts, and skipped occurrences are not automatically replayed. Step retry settings apply after a workflow starts. Studio shows trigger and run history. [Delivery guarantees](https://mastra.ai/docs/workflows/scheduled-workflows#delivery-guarantees) · [Workflow retries](https://mastra.ai/docs/workflows/error-handling#retries) | Add a publish step with a GitHub credential and a writable checkout or the Git API. Keep it safe to retry if the push succeeded before the workflow recorded completion. [Git ref updates](https://docs.github.com/en/rest/git/refs#update-a-reference) |

GitHub Actions fits the existing Git-backed data model with the fewest moving parts. eve becomes relevant for an agent that can investigate an anomaly or discuss it in a channel. Mastra becomes relevant if a larger workflow needs persisted state, step recovery, or operator controls.

## Proposed first pass

1. **Confirm source and rights.** The NHL's site terms restrict unauthorized automated collection and copying or distribution. Confirm that the chosen feed permits automated collection and the intended Git archive before enabling either, or use a licensed feed with those rights. The official game and event summaries for `2026020270` verify a 5–4 New Jersey overtime win and provide per-player statistics. The [candidate JSON endpoint](https://api-web.nhle.com/v1/gamecenter/2026020270/boxscore) could not be verified in this evaluation. Verify that the source covers team totals, skaters, goalies, and any required scoring or penalty detail before committing to a payload contract. [NHL terms](https://www.nhl.com/info/terms-of-service) · [Official game summary](https://www.nhl.com/scores/htmlreports/20262027/GS020270.HTM) · [Official event summary](https://www.nhl.com/scores/htmlreports/20262027/ES020270.HTM)
2. **Refresh and reconcile.** Reuse the game and poster refreshers. Stage their output together and validate the pair before publication. Store one box score per completed game at `data/boxscores/<season>/<gameId>.json` with a schema version, source URL, retrieval time, and the stats. Validate each box score against its game ID, teams, and final score. Recheck recent finals for corrections and backfill missing IDs in bounded batches. Keep the prior valid pair when the score and standings feeds disagree. Record missing or invalid box scores as outstanding work so the next run can retry them without blocking a valid score and poster update. [Existing refreshers](../scripts/refresh-nhl-games.mjs) · [Poster refresh](../scripts/refresh-nhl-poster.mjs) · [Existing data tests](../tests/nhl-games.test.mjs)
3. **Publish once after validation.** Serialize scheduled and manual publishing runs on the default branch with the same concurrency group. Validate and build before a single data-only, fast-forward push. If the branch advances, refresh against the new tip before publishing. Compare data before updating retrieval timestamps so an identical run creates no commit. Record the last successful check and outstanding box score IDs in the run summary. A push with the built-in token does not trigger the existing push-validation workflow, so run the relevant checks in the publishing job itself. [Workflow concurrency](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#concurrency) · [Existing validation workflow](../.github/workflows/validate.yml) · [Token-triggered events](https://docs.github.com/en/actions/concepts/security/github_token#when-github_token-triggers-workflow-runs)
4. **Verify production freshness separately.** The site reads bundled snapshots, so a successful data commit needs a production deployment before the new scores appear. Verify that the connected Vercel project builds the bot commit and that the deployed API shows the updated result. The current branch rules and Vercel deployment behavior for bot commits were not verified in this evaluation. [Repository deployment contract](../data/README.md) · [Vercel Git integration](https://vercel.com/docs/git/vercel-for-github)

Pilot the same collector locally in a temporary directory before turning on the schedule. Check that a second run produces no data diff, a corrected stat updates the same game file, and a failed or missed run recovers the outstanding IDs. These checks apply the project's requirements for validation before writes, repeatable operations, and a single writer for shared data. [Project data workflow](../.agent-sources/ratstack/README.md)
