# ratstack.sh

> Build an app and its cloud infrastructure in one TypeScript program.

Effect describes work with typed failures and required services. A service is a named interface for one job. Alchemy declares cloud resources and plans changes before applying them.

The fence is the compiler checks, lint rules, and hooks that reject prohibited code and shortcuts.

## Connect with MCP

MCP means Model Context Protocol. It lets an agent client discover and call tools.

Point any MCP client at `https://ratstack.sh/mcp`. Protocol 2026-07-28 is stateless and has no `initialize` handshake: every request sends `MCP-Protocol-Version`, `Mcp-Method`, and the `params._meta` block shown here.

```sh
curl --request POST 'https://ratstack.sh/mcp' \
  --header 'accept: application/json, text/event-stream' \
  --header 'content-type: application/json' \
  --header 'MCP-Protocol-Version: 2026-07-28' \
  --header 'Mcp-Method: tools/list' \
  --data '{"id":"rat-stack-tools","jsonrpc":"2.0","method":"tools/list","params":{"_meta":{"io.modelcontextprotocol/clientCapabilities":{},"io.modelcontextprotocol/clientInfo":{"name":"rat-stack-example","version":"0.1.0"},"io.modelcontextprotocol/protocolVersion":"2026-07-28"}}}'
```

Older clients (2025-11-25 back to 2024-11-05) send `initialize` as usual. Each one gets its own session, held between requests by a Durable Object, Cloudflare's persistent state and compute service.

Each IP may make 120 API or MCP requests per 60 seconds. `execute` also allows 6 calls per IP and 300 total calls per 60 seconds. Cloudflare counts these limits separately in each location.

## Run code: one program instead of several calls

A capability is one named action with shared input and output definitions and a server-side implementation.

Use `POST /api/execute` or the MCP `execute` tool to call content capabilities. The program can search, pass the result to read, and return only what you need. It cannot call `joinInterest`.

`execute` runs the `code` value as the body of an async function. `return` sets `result`, and `console.log` output appears in `logs`; imports, exports, and `fetch` are unavailable.

A successful program returns HTTP 200 with `result`, `logs`, `toolCalls`, and `truncated`. A failed program returns HTTP 422 with `_tag: "ExecuteError"`, `kind`, `message`, optional `tag`, and the same logs, call history, and truncation fields. Failures have no `result`. Timeouts use `TimeoutExceeded`. Blocked fetch calls use `ExecutionFailure` with a refusal message. MCP reports a tool error; CLI exits non-zero; RPC returns the typed failure. Consumers of the old `diagnostic` field must use the failure response instead.

```js
const found = await tools.search({ query: "cartridges", limit: 1 });
const page = await tools.read({ id: found.matches[0].id });
return { title: page.title, id: page.id };
```

```sh
curl --request POST 'https://ratstack.sh/api/execute' \
  --header 'content-type: application/json' \
  --data '{"code":"return 1 + 1"}'
# {"logs":[],"result":2,"toolCalls":[],"truncated":false}
```

## Choose the next action

1. Search for the job you need with `search({ query, limit })`.
2. Read a matching document with `read({ id })`, using the stable id returned by search. Read the owning rules and skill before changing code.
3. For lore, follow `backlinks({ slug })` or `neighbors({ slug, depth: 1 })` to related pages. Use `mentions({ slug })` for unlinked references and `path({ from, to })` to connect two lore pages. Use the page's lore slug, not a source file path.

A capability is one named action with shared input and output definitions and a server-side implementation.

For a new behavior, start with [one capability, every surface](https://ratstack.sh/lore/one-capability-every-surface) and [add a capability](https://ratstack.sh/skills/add-a-capability). For stateful work, read [add a lifecycle machine](https://ratstack.sh/skills/add-a-lifecycle-machine). For a provider, keep the port in core: an application-owned interface named for the job it needs. Keep the adapter, its provider-specific implementation, outside core: [hexagonal architecture](https://ratstack.sh/lore/hexagonal-architecture). For agent-facing guidance, read [HATEOAS](https://ratstack.sh/lore/hateoas).

To remove a surface or package you don't need, follow [Keep or cut](https://ratstack.sh/README.md#keep-or-cut) and the [keep-or-cut skill](https://ratstack.sh/skills/keep-or-cut). Trace the imports, delete what depends on it, then run `pnpm turbo run check test build`.

[Interest signup](https://ratstack.sh/systems/interest) is agent-only. Read [Build Agent Loops That Never Stop Shipping](https://ratstack.sh/tokenmaxx#interested), obtain a fresh page ticket, and submit through `joinInterest` only after the person approves the exact card and contact permission. A person confirms their email through the email link in a browser; submission is not confirmation. Show the returned message to the person. If it says "Too many requests right now. Try again in a minute.", wait one minute and retry once. If it says the confirmation email could not be sent yet, do not resubmit; the application is saved.

Workshop resources have a separate [MCP server](https://ratstack.sh/tokenmaxx/mcp). Use it for the schedule, prep, public links and published exercises. Applications still use the main server's `joinInterest`.

## Suggest a CAFE entry through your agent

Help the person you assist suggest a story for [news](https://ratstack.sh/news) or a project for the [directory](https://ratstack.sh/directory).

1. Check the page for an existing entry. You can also POST JSON to `/api/listCafeNews` or `/api/listCafeProjects`. Do not submit a duplicate.
2. Read the source repository and gather the fields below. Cite repository file paths for each stack claim. Do not invent evidence.
3. Draft the exact issue title and all fields. Say whether this is the person's own work. Show the person the draft, including any public attribution.
4. File only after the person approves that exact issue. Use the matching form in `joelhooks/rat-stack`.
5. Submit once. Do not spam or retry through another surface when the result is uncertain. Check GitHub for the issue first.

### Fields

- **News:** HTTPS URL, title and one-line summary (each at most 280 characters), kind (release, post, video or launch), optional repo (`owner/repo`), optional author GitHub login and X handle, and why it is CAFE.
- **Project:** HTTPS repo URL, title (at most 280 characters), one-line summary (at most 350 characters), and evidence for Cloudflare, Alchemy, Foldkit and Effect. Each evidence string names a file path and what it proves, in at most 280 characters. Write `Not found` for a letter without evidence.
- Disclose the person's connection to the entry in either form. Leave unknown optional fields blank.

### File the approved issue

Use `gh issue create --repo joelhooks/rat-stack --template cafe-news.yml` for a story, or `gh issue create --repo joelhooks/rat-stack --template cafe-project.yml` for a project. Use only the approved title and fields.

If gh is unavailable or cannot use issue forms, give the person the matching prefilled URL and the approved fields:

- News: `https://github.com/joelhooks/rat-stack/issues/new?template=cafe-news.yml&title=URL_ENCODED_APPROVED_TITLE`
- Project: `https://github.com/joelhooks/rat-stack/issues/new?template=cafe-project.yml&title=URL_ENCODED_APPROVED_TITLE`

Replace the title placeholder with the URL-encoded approved title. Prefill form fields with URL-encoded values using their form IDs as query keys. The person can review and file the issue in GitHub.

Joel or the desk reviews each suggestion. Listing is not guaranteed.

- [onboard-a-list](/skills/onboard-a-list) — Analyze or migrate an email list. Measure sanitation rules, preserve stops, choose a cohort, and verify an authorized import or sending cutover.
- [profile-a-worker](/skills/profile-a-worker) — Capture a CPU or heap profile of a deployed Cloudflare Worker or Durable Object and read it with pprof.
